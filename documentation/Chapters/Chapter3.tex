\chapter{Preparación y Preprocesamiento}
\label{Chapter3}

Este capítulo describe el proceso de preparación de datos realizado antes del entrenamiento del modelo. Se detalla cómo se construyeron los conjuntos de \textit{train}, \textit{validation} y \textit{test}, los pasos de preprocesamiento aplicados a las imágenes y las técnicas de \textit{data augmentation} utilizadas para mejorar la capacidad de generalización del modelo. Asimismo, se justifica la necesidad de normalizar y estandarizar las entradas de acuerdo con los requerimientos de la arquitectura \textit{Vision Transformer} seleccionada.

\section{División del dataset}

A partir del conjunto limpio generado en la etapa de análisis exploratorio, se definió una división estratificada en tres subconjuntos: entrenamiento, validación y prueba. La estratificación se realizó tomando como variable objetivo el atributo \textit{articleType}, con el fin de preservar la proporción relativa de clases en cada partición y evitar sesgos durante el entrenamiento.

El dataset final se dividió con los siguientes porcentajes:

\begin{itemize}
    \item \textbf{70\%} para entrenamiento.
    \item \textbf{15\%} para validación.
    \item \textbf{15\%} para prueba.
\end{itemize}

La división se realizó mediante una estrategia robusta para manejar clases con baja frecuencia. Aquellos tipos de producto con menos de cinco muestras fueron agrupados en una clase adicional \textit{RARE\_CLASS} con el fin de evitar errores de estratificación. Esta técnica permitió mantener la coherencia estadística de los subconjuntos sin perder información relevante.

Además de los archivos \texttt{train.csv}, \texttt{val.csv} y \texttt{test.csv}, se generaron carpetas independientes con las imágenes correspondientes a cada partición, asegurando un pipeline reproducible y coherente con las buenas prácticas de \textit{cookiecutter data science}:

\begin{verbatim}
data/
  processed/
    images/
      train/
      val/
      test/
\end{verbatim}

Esta organización facilita la carga del dataset en PyTorch, reduce errores de lectura y estandariza el flujo de experimentación.

\section{Preprocesamiento de imágenes}

El preprocesamiento se orientó a adaptar las imágenes del dataset a los requerimientos del modelo \textit{Vision Transformer}, cuya arquitectura espera entradas cuadradas y normalizadas. A partir del análisis realizado en el capítulo de EDA, se observaron las siguientes características relevantes:

\begin{itemize}
    \item Todas las imágenes poseen tamaño uniforme de \textbf{60×80 píxeles}, inferior al requerido por ViT.
    \item La relación de aspecto es constante, lo que facilita el escalado sin distorsión.
    \item La calidad de las imágenes (luminosidad, contraste, nivel de enfoque y saturación) es adecuada para un modelo de clasificación supervisada, aunque con variabilidad suficiente como para beneficiar el uso de técnicas de \textit{augmentation}.
\end{itemize}

En consecuencia, se aplicaron los siguientes pasos de preprocesamiento:

\begin{enumerate}
    \item \textbf{Redimensionamiento a 224×224 píxeles.}  
    Este tamaño es estándar para modelos basados en Transformers y permite aprovechar pesos preentrenados en ImageNet.

    \item \textbf{Conversión a tensor y normalización.}  
    Se aplicaron las estadísticas de ImageNet:
    \[
        \mu = (0.485, 0.456, 0.406), \quad
        \sigma = (0.229, 0.224, 0.225)
    \]
    con el fin de estabilizar el entrenamiento y lograr compatibilidad con pesos preentrenados.

    \item \textbf{Validación de integridad.}  
    Se eliminaron imágenes corruptas o no legibles y se depuraron filas del CSV que no podían vincularse a su archivo correspondiente.
\end{enumerate}

Este pipeline garantiza que todas las imágenes de entrada cumplen el formato necesario para maximizar el desempeño del modelo.

\section{Data augmentation}

Dado que las imágenes del dataset son relativamente pequeñas y presentan poca diversidad visual en términos de iluminación, pose y fondo, se definió un conjunto de transformaciones destinadas a aumentar la variabilidad sintética del conjunto de entrenamiento. Esto reduce el riesgo de sobreajuste y mejora la robustez del modelo.

Las transformaciones aplicadas durante el entrenamiento fueron:

\begin{itemize}
    \item \textbf{Random Horizontal Flip:} simula variaciones naturales en pose y orientación.
    \item \textbf{Color Jitter (brillo, contraste, saturación):} incrementa la tolerancia del modelo a condiciones de iluminación heterogéneas.
    \item \textbf{Random Rotation (±15°):} introduce pequeñas perturbaciones para mejorar la invariancia rotacional.
    \item \textbf{Affine transformations:} ligeras modificaciones de escala o traslación, cuando aplicable.
\end{itemize}

Estas transformaciones se aplican de manera estocástica únicamente al conjunto de entrenamiento. El conjunto de validación y prueba solo recibe las transformaciones estrictamente necesarias (redimensionamiento y normalización), con el objetivo de realizar una evaluación justa y reproducible del modelo.

\section{Construcción del PyTorch Dataset}

Con las particiones y el preprocesamiento definidos, se implementó una clase \texttt{PyTorch Dataset} capaz de:

\begin{itemize}
    \item Cargar imágenes desde las carpetas correspondientes a cada split.
    \item Aplicar automáticamente las transformaciones definidas para cada partición.
    \item Mapear cada imagen hacia sus atributos objetivos codificados.
    \item Soportar clasificación multi-etiqueta mediante vectores binarios por atributo.
\end{itemize}

Este diseño permite integrar el dataset de manera directa con el \textit{DataLoader} de PyTorch, facilitando el batching, el shuffle y la paralelización en CPU.

\section{Selección de modelo}

Para la tarea de clasificación multiclase sobre imágenes de productos de e-commerce se seleccionó como modelo base un \textit{Vision Transformer} de tipo \texttt{ViT-B/16}, en su implementación de \texttt{torchvision} con pesos preentrenados en ImageNet. Esta variante (Base, con tamaño de parche $16 \times 16$) se adaptó al problema reemplazando la \textit{classification head} original por una capa totalmente conectada ajustada al número de clases del dataset, manteniendo el resto de la arquitectura estándar y realizando \textit{fine-tuning} sobre el dominio objetivo.

\subsection{Descripción de la arquitectura ViT-B/16}

\texttt{ViT-B/16} sigue la arquitectura de los \textit{Vision Transformers} clásicos: la imagen de entrada ($224 \times 224$) se divide en parches no solapados de $16 \times 16$ píxeles, que se aplanan y proyectan linealmente a vectores de \textit{embedding}. A esta secuencia se añade un token especial de clasificación (\texttt{[CLS]}) y se suman \textit{positional embeddings} entrenables.

La secuencia resultante se procesa mediante una pila de bloques \texttt{Transformer encoder}, cada uno compuesto por una capa de \textit{Multi-Head Self-Attention} (MHSA), una red \textit{feed-forward} por token y mecanismos de normalización y residuales. Finalmente, la representación del token \texttt{[CLS]} se pasa a la \textit{classification head}, una capa lineal ajustada al número de clases.

\subsection{Criterios de selección}

A continuación se describen los principales criterios que motivaron la elección de \texttt{ViT-B/16} frente a otras variantes de \textit{Vision Transformers}:

\begin{itemize}
\item Adaptación al dominio visual del dataset: Como se mencionó anteriormente, el dataset objetivo para el entrenamiento pertenece al dominio del e-commerce. Las imágenes presentan productos centrados, fondos neutros y buena calidad visual, condiciones adecuadas para que el mecanismo de atención global de ViT capture patrones discriminativos relevantes. La tarea concreta de clasificación sobre el atributo \texttt{articleType}, con más de 100 clases, demanda un modelo con alta capacidad de representación para distinguir diferencias sutiles entre prendas y accesorios.

\item Preentrenamiento robusto y transferible: \texttt{ViT-B/16} ha sido preentrenado sobre ImageNet con una configuración ampliamente validada. Esto permite aprovechar representaciones generales de alto nivel y realizar una adaptación eficiente al dominio específico con un número moderado de epochs y tamaño de batch reducido.

\item Compromiso entre capacidad y coste: Frente a variantes más pequeñas (como \texttt{ViT-Ti} o \texttt{ViT-S}), \texttt{ViT-B} ofrece mayor capacidad de representación, lo que resulta ventajoso en un problema con gran número de clases. Al mismo tiempo, evita el alto costo computacional y el riesgo de sobreajuste asociado a variantes más grandes (\texttt{ViT-L}, \texttt{ViT-H}), resultando adecuada para entrenamientos limitados en tiempo y memoria.

\item Tamaño de parche equilibrado ($16 \times 16$): Este tamaño proporciona un balance eficaz entre resolución espacial y eficiencia computacional. Capta suficiente detalle local para discriminar entre productos similares, sin comprometer la viabilidad del entrenamiento con recursos restringidos.

\item Explicabilidad del modelo: La arquitectura estándar de \texttt{ViT-B/16} facilita el análisis e interpretación de las atenciones generadas por el modelo, una característica valiosa en contextos de e-commerce donde se requiere trazabilidad en las decisiones del clasificador.
\end{itemize}

\section{Configuración de entrenamiento}

Una vez definido el modelo base, se implementó un \textit{pipeline} de entrenamiento en el script \texttt{train.py} encargado de orquestar la construcción de los \textit{DataLoaders}, la inicialización del \textit{Vision Transformer}, el bucle de optimización y el registro de métricas en \texttt{MLflow}. El flujo general es el siguiente:

\begin{enumerate}
    \item Carga de los archivos \texttt{train.csv} y \texttt{val.csv} y de las carpetas de imágenes correspondientes.
    \item Construcción de los conjuntos de entrenamiento y validación mediante la clase \texttt{ImageDataset}, que aplica las transformaciones definidas (redimensionamiento, normalización y, opcionalmente, \textit{data augmentation}).
    \item Inicialización del modelo \texttt{ViT-B/16} preentrenado en ImageNet y adaptación de la \textit{classification head} al número de clases del atributo \texttt{articleType}.
    \item Entrenamiento del modelo durante un máximo de \textbf{10 épocas}, monitorizando la pérdida y las métricas de validación.
    \item Aplicación de \textit{early stopping} basado en la pérdida de validación, con una paciencia de \textbf{5 épocas} sin mejora.
    \item Almacenamiento del mejor modelo en disco y registro de artefactos (modelo y mapeo \texttt{class\_to\_idx}) en \texttt{MLflow}.
\end{enumerate}

\subsection{Función de pérdida}

Para la tarea de clasificación multiclase se utilizó la función de pérdida \textbf{CrossEntropyLoss} de PyTorch. Esta elección es estándar en problemas donde cada imagen pertenece exactamente a una única clase entre $K$ posibles, y permite optimizar directamente la probabilidad de la clase correcta a partir de los \textit{logits} producidos por la \textit{classification head}.

Inicialmente se consideró incorporar \textbf{ponderación por clase (\textit{class weighting})} para mitigar el desbalance observado en el atributo \texttt{articleType}. Sin embargo, se optó por comenzar con una configuración base sin pesos, utilizando en cambio métricas complementarias (F1 macro y F1 ponderado) para evaluar el impacto del desbalance. La incorporación de \textit{class weighting} se deja identificada como trabajo futuro para profundizar en la corrección de dicho desbalance sin introducir complejidad adicional en esta primera versión del sistema.

\subsection{Optimizador y regularización}

Como algoritmo de optimización se empleó \textbf{AdamW} con un \textit{learning rate} inicial de $\text{lr} = 3 \times 10^{-4}$ y un término de \textit{weight decay} de $1 \times 10^{-4}$. La elección de \texttt{AdamW} se debe a que combina la adaptatividad de Adam (que ajusta de forma independiente el \textit{learning rate} de cada parámetro) con una formulación de \textit{weight decay} desacoplada, lo que ha demostrado funcionar especialmente bien en \textit{Transformers} preentrenados.

El valor de $\text{lr} = 3 \times 10^{-4}$ sigue las recomendaciones habituales para \textit{fine-tuning} de modelos preentrenados: lo suficientemente bajo como para no desestabilizar los pesos aprendidos en ImageNet, pero alto como para permitir la adaptación al nuevo dominio con un número limitado de épocas. El término de \textbf{weight decay = $1 \times 10^{-4}$} introduce una regularización L2 moderada que ayuda a evitar sobreajuste en un problema con más de 100 clases y tamaño de dataset acotado.

\subsection{Scheduler de \textit{learning rate}}

En la configuración actual no se empleó un \textit{scheduler} explícito del \textit{learning rate}. Se optó por mantener un \textit{learning rate} fijo de $3 \times 10^{-4}$ durante todo el entrenamiento para simplificar el diseño experimental y poder aislar el efecto de otros componentes (data augmentation, \textit{early stopping}, etc.). En trabajos futuros se considera incorporar \textit{learning rate scheduling} (por ejemplo, \textit{cosine decay} o \textit{step decay}) para explorar mejoras adicionales de desempeño una vez fijada la configuración base.

\subsection{Número de épocas, \textit{batch size} y \textit{early stopping}}

El entrenamiento se configuró con un máximo de \textbf{10 épocas} y un \textit{batch size} de \textbf{32} imágenes. El \textit{batch size} se eligió como compromiso entre el uso eficiente de la memoria GPU disponible, la estabilidad de las estimaciones de gradiente y un tiempo de entrenamiento razonable para iterar sobre distintos experimentos.

Dado que el modelo parte de pesos preentrenados, no se espera necesitar un número muy elevado de épocas para converger. Para evitar sobreajuste y entrenamientos innecesariamente largos, se implementó un mecanismo de \textbf{early stopping} monitorizando la pérdida de validación (\texttt{val\_loss}) con una paciencia de \textbf{5 épocas}. Si la pérdida de validación no mejora en cinco iteraciones consecutivas, el entrenamiento se detiene y se conserva el modelo con mejor desempeño observado.

Este esquema permite adaptarse dinámicamente al punto de saturación del modelo: en experimentos preliminares se observó que la pérdida de validación tiende a estabilizarse antes de alcanzar las 10 épocas, por lo que el \textit{early stopping} ayuda a reducir el tiempo de entrenamiento sin sacrificar rendimiento.

\subsection{Data augmentation durante el entrenamiento}

Durante el entrenamiento se aplicaron técnicas moderadas de \textit{data augmentation} sobre el conjunto de entrenamiento, manteniendo únicamente el redimensionamiento y la normalización en validación. Las transformaciones utilizadas fueron:

\begin{itemize}
    \item \textbf{RandomHorizontalFlip} con probabilidad 0{,}5.
    \item \textbf{ColorJitter} (brillo, contraste, saturación y tono) aplicado con probabilidad 0{,}5.
    \item \textbf{RandomRotation} de hasta $\pm 10^\circ$.
\end{itemize}

Estas transformaciones buscan aumentar la variabilidad efectiva del dataset sin alterar la semántica de la clase (por ejemplo, una remera sigue siendo la misma clase aunque se vea ligeramente más brillante o rotada). La decisión de utilizar augmentations suaves se basó en las observaciones del EDA: fondos mayormente neutros, productos centrados y buena calidad de imagen, donde deformaciones agresivas podrían introducir artefactos irreales.
